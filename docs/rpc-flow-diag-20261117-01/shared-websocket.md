# Shared WebSocket admission and isolated z170-1 rehearsal

**NO-GO for a live A/B trial.** This work continues `26a8a94` and `cf651e7`. The experiment requires an explicit server flag, a separately built preload and a matching WebSocket subprotocol. The work used read-only production inspection and private builds, listeners, sockets, profiles and processes.

The follow-up records the [final isolated reruns, acceptance thresholds, and production procedure](deployment-readiness.md).

## Ownership, ordering and deadlock

- The forward and reverse data allowances are 448 KiB and 64 KiB, for 512 KiB per connection. Two admitted generations give a 1-MiB aggregate ceiling. A sender charges a complete fragment of up to 48 KiB plus its envelope and conservative deflate and WebSocket framing overhead before handing it to the WebSocket API. A valid cumulative receipt deletes each ticket once. Error or disconnect clears the map, rejects parked writers and removes the connection slot. Node send errors close the generation. An independent local `bufferedAmount` check covers queued sender bytes.
- Sync IPC producers stage up to 16 MiB of encoded bytes and 128 ordinary envelopes per direction and connection. Reassembly allocates up to one 16-MiB envelope. The browser app-host receive queue allows 512 KiB and the host pre-listener queue allows 256 KiB per port. A connection can park four host byte writes of up to 81,920 bytes each before base64 encoding. The host also splits larger upstream byte chunks into ordered views of that atomic maximum. Rechunking holds at most a 1-MiB source backing buffer and 2 MiB across concurrent split sources on the connection. Overflow, invalid framing and failed progress close the generation visibly. For a void IPC call, connection failure is the notification for an undeliverable message.
- The transport receipt acknowledges a fragment at bounded reassembly or dispatch. It progresses while a stream reader waits. RPC credit still depends on completion of the writer operation. The staged host caps the adaptive window at 1,771,040 estimator bytes and checks credit again immediately before encoding. Cancellation of a parked writer prevents it acquiring an operation ID.
- Only a void RPC resolution can bypass a partially sent ordinary message. It names an import already allocated by the opposite endpoint and carries no new exports. It remains behind frames already handed to the WebSocket. The priority lane allows 8 KiB of issued reservations and 8 KiB of queued charges per direction, with a 512-byte serialized envelope limit. Close, errors, value-carrying replies, clocks and notifications all preserve ordinary FIFO.
- Receipts require neither application consumption nor opposite-direction credit. Their independent 256-byte local allowance permits progress with full data ledgers. An idle heartbeat runs at half the deadline and uses one priority ticket. An idle half-open connection or a stalled transfer expires independently. An ordered remote cancellation can wait behind earlier bulk in the same direction. Connection expiry bounds a peer that never drains those bytes.

## Resource and A/B validation

Both benchmark variants use shared admission, the same 256-KiB initial window and the same host ceiling. A has a 64-KiB minimum and B has a 512-KiB minimum. The exact installed A used for rollback uses legacy framing. Chromium ran two connections with two streams each. Each healthy mixed-traffic client submitted a 2.10-MB reverse invoke, received a 2.10-MB UTF-8 notification, and checked byte integrity and small IPC order. Linux packet tests used private loopback netem with 1500-byte MTU. Delay changed from 25 ms to 100 ms with 20-ms jitter during transfer. The bandwidth profile used 8 Mbit/s. The parent qdisc and private qdisc teardown were checked.

Throughput is decoded stream MiB per second from first production to last consumption across both clients, exclusive of IPC bytes. Counters track data tickets, staged encoded payloads, reassembly allocation, decoded producer-to-consumer backlog, estimated RPC flight, native WebSocket buffering, TCP TX and process RSS separately. The conservative bidirectional reservation bound adds each browser's peak to the simultaneous host peak. The static split enforces the exact combined ceiling at every instant.

The packet comparison uses the median of two balanced AB/BA pairs. Application profiles use one A/B pair each. The source checks repeat cancellation and disconnect on the final rechunking code and add upstream error and maximum-atomic cases.

## Rehearsal and rollback

Production inspection established the loopback `node-22` listener, its parent mode-file launcher and Tailscale TLS-terminated TCP forwarding to `127.0.0.1:8214`. The active launcher runs in an unlimited session scope. Its exact source was copied into a transient user service. The private release pointer switched only after the launcher and child exited. The launcher accepts normal, diagnostics and stop modes. Release selection and recovery after a crash require an external action.

The harness used Desktop host/browser assets, unchanged `codex_remote_proxy`, websocat and a real Codex 0.169.0 app-server over an owned Unix socket. It used a TLS-terminated TCP relay on a distinct loopback port with a temporary certificate. Bubblewrap hid live home and launcher paths in private mount, network, PID and IPC namespaces. Desktop, Chromium, the app-server, the CLI proxy and TLS relay shared a verified `memory.max=2147483648`, `memory.swap.max=0` cgroup. The private app-server used a socket accessible by inode across the staged mounts.

- The unchanged CLI proxy initialized against the private app-server. All three releases returned HTTP 200 over verified TLS 1.3 and answered the private directory IPC probe. Chromium negotiated legacy → `codex-ipc-budget-v1` → legacy.
- A, B and restored A each delivered two concurrent 1-MiB response bodies with identical SHA-256. The harness calls the real packaged Desktop fetch service through its app-host RPC port. A dedicated rehearsal preload maps one synthetic `data:` URL to the contained HTTP fixture. The initial B run rejected upstream chunks larger than the extracted fixture's atomic cap. Rechunking resolved that failure. B's successful body probe recorded 262,144 B of retained raw source bytes, 446,714 B of forward reservations and 350,032 B of native WebSocket buffering.
- A's shutdown released the listener and reaped its Desktop child. A forced B child crash left it down until the actual launcher observed a mode change. That transition restored the listener, and Chromium reloaded through a new WebSocket upgrade. The recovered child stopped cleanly and the final A release used the same captured command, executable, cwd, mode, environment and artifact hashes as initial A. Final A shutdown released the listener and reaped the child.
- The full-process-tree cgroup peaked at **958.2 MiB** with zero OOM events. An isolated B Desktop RSS sample reached 305.4 MiB. The earlier extracted fixture's stop threshold for its Node host was 256 MiB.
- Chromium reached the logged-out app and live IPC. The authenticated editor gate remained incomplete. The rehearsal used a disposable profile with no credentials. [Rehearsal evidence](shared-websocket-rehearsal.json).

The normalized tar SHA-256 over the staged A's `src/server` and `scratch/asar` matched the production snapshot (`de25bc2c298d15e1e0c1a9af5610476118330852e2e14e5e1020898bf71c92d2`). The returned A was checked against the same tree, including the entrypoint, Desktop bundles and compressed preload, as well as its captured command, cwd, executable, mode and environment digest. The private paths, port, profile, TLS cert and loopback body fixture intentionally differ from production. [Rehearsal harness](../../scripts/diagnostics/rpc-shared-rehearsal.cjs).

## Deployment gates

1. Exercise an authenticated disposable account through actual Desktop bootstrap responses, the interactive editor, mixed notifications and reconnect under the final containment. The offline body fixture and private app-server prove the transport paths and isolate the auth gap. Confirm an acceptable remote cancellation latency when earlier same-direction bulk IPC is in flight.
2. Establish full-stack component stop thresholds and baseline headroom. The observed Desktop RSS exceeds the extracted fixture's 256-MiB threshold even with ample cgroup headroom. Record agreed workload and stop criteria before any trial.
3. Approve and rehearse the production release handoff. The exact mode-file launcher was exercised. It has no release selector, forced-stop timeout, automatic recovery or strong readiness gate. The private harness supplied the release pointer and health checks. The production session owner must confirm how those operations run under the real parent session and Tailscale service. The private TLS byte relay leaves Tailscale identity, routing, certificate lifecycle and real tailnet buffering to be verified in a separate authorized environment. Existing tabs also need an explicit reload when changing legacy/bounded protocol versions, since an incompatible upgrade cannot reach the browser's reload-on-open handler.

The experiment stays disabled. An authenticated, contained rehearsal, operational acceptance and separate explicit authorization are required before a live trial.

## Reproduction

Use a new `/tmp/rpc-shared.*` stage. Copy the z170-1 launcher, read-only A release snapshot, clean Desktop 26.1007.30912 artifacts for B, and dependencies. In the copy, run `rpc-shared-artifacts.cjs STAGE/B 512k`, `npm run build:server`, and `CODEX_WEB_SHARED_TRANSPORT=1 npm run build:browser`. The browser build regenerates the affected compressed assets.

Set `PLAYWRIGHT_MODULE` and `CHROMIUM_PATH` to local installations. Use a fresh output path and a transient user service with `MemoryMax=2G`, `MemorySwapMax=0`, and `OOMPolicy=stop`. Run `rpc-concurrency.cjs OUTPUT` with `RPC_CONCURRENCY_POLICIES=shared-stop` and select profiles with `RPC_CONCURRENCY_PROFILES`. For packet tests, set `RPC_PARENT_NETNS` and `RPC_PARENT_QDISC` from the parent and use `unshare --user --map-root-user --net node rpc-netem.cjs OUTPUT` in the transient unit.

For the stack rehearsal, place the launcher and both harness files `rpc-shared-rehearsal.cjs` and `rpc-core.cjs` in `control/`. Stage the CLI and proxy in `bin/`, add a localhost certificate/key in `control/`, and create a disposable `profile/` and `work/`. In bubblewrap bind the stage writable, mask the live home, mount a fresh `/tmp` and bind the stage's mode-0700 `control/daemon` directory at `/tmp/codex-daemon-UID`. Set home, Codex home, XDG and temporary paths inside the profile and bind the Chromium dependencies read-only. Set `REHEARSAL_PARENT_NETNS` and `REHEARSAL_PRODUCTION_HOME` for the isolation checks. Run `node control/rpc-shared-rehearsal.cjs STAGE` in the transient unit.

The current harness also reads the recorded source sizes from `control/bootstrap-chunks.csv`. Copy [the correlated timing CSV](../bootstrap-diag-20261117-01/chunk-timings.csv) to that path before running it.
